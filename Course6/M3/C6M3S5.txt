You saw the Python implementation of autoregressive family models. To do this, we use the ARIMA function from statsmodel library, which provides a unified framework for building AR, MA, ARMA, and ARIMA models.

 

The ARIMA function is controlled through the order parameter, specified as a three-tuple Equation. Here,

Equation denotes the autoregressive order,

Equation denotes the order of differencing, and

Equation denotes the moving average order.

 

By choosing appropriate values of  Equation, Equation, and Equation the same function can be used to construct different models from the autoregressive family.

To build an autoregressive (AR) model, we set a non-zero value for Equation and keep Equation and Equation.For the superstore data set, a moderate value of Equationis chosen to balance correlation strength and model complexity. The model is then fitted using the ARIMA function with the specified order, and predictions are generated on the testing period.

The AR model captures some of the underlying structure in the data, but discrepancies remain between the predicted and actual values. This indicates that relying only on past observations may not be sufficient to explain all the patterns present in the series.
 
Next, we consider the moving average (MA) model, which focuses on past forecast errors rather than past values. To construct an MA model, we set Equationand Equation, and choose a non-zero value for Equation. This model helps capture short-term dependencies driven by shocks or noise in the data.

The MA model reflects the overall movement of the series reasonably well, but it struggles to account for more complex patterns. This highlights the limitations of using only past errors without incorporating past observations.
 
Having explored AR and MA models separately, we then move to the ARMA model, which combines both autoregressive and moving average components. In this case, both Equation and Equation are set to non-zero values while keeping Equation. This allows the model to account for dependencies arising from both past values and past errors

The ARMA model captures the structure of the data more effectively than AR or MA alone. However, performance on unseen data can still be affected when the series exhibits non-stationarity or evolving patterns.
 
To address non-stationarity, we extend the model to ARIMA by introducing differencing. By setting Equation, the model accounts for trends present in the data before applying AR and MA components. While this improves the model’s ability to track changes over time, it may still fall short if seasonal patterns are present.
 
Finally, we moved to seasonal ARIMA (SARIMA) models. To implement SARIMA in Python, we use the SARIMAX method from statsmodels, which allows us to specify both non-seasonal and seasonal components. In addition to the order parameter Equation, SARIMA uses a seasonal_order parameter of the form Equation, where Equation represents the seasonal period.

Incorporating seasonality enables the model to capture repeating patterns that occur at regular intervals. For the superstore data set, including seasonal terms leads to noticeably improved alignment between predicted and actual values.
 

This reinforces an important insight: explicitly modelling seasonality can significantly improve forecast accuracy. A similar observation was made earlier with exponential smoothing models, where Holt–Winters methods performed better by accounting for seasonal behaviour alongside level and trend.

### Subpart 1 - Autoregressive (AR) Method

We will begin by fitting a basic autoregressive model to the training data and analyse its performance. We will use the *ARIMA* method from *statsmodels* to build the model.

**Note:** The *ARIMA* method can also be used to implement other autoregressive models.

# Import 'ARIMA' from 'statsmodels' for building autoregressive models
from statsmodels.tsa.arima.model import ARIMA

The parameter of interest in the *ARIMA* method is the *order* parameter. It is a 3-tuple of the form $(p, d, q)$ with the default value as $(0, 0, 0)$.

For the AR method, we will specify the first value in this tuple. This is the $p$ value or the lag order obtained from the PACF plot.

# Use the 'plot_pacf' method to look at the partial autocorrelation values for the training data for various lag orders
# Note: The 'plot_pacf' method assumes stationarity of time series, so we will use the 'df_boxcox_diff' data
# Note: Since differencing results in a missing value at the beginning, we must exclude it
plot_pacf(x = df_boxcox_diff[1:], color = 'blue', vlines_kwargs = {'colors': 'blue'});

# Fit an AR model to the transformed training data with lag order 9 and view its optimal parameter values
# Note: You may try other suitable lag order values as well
# Note: ARIMA(9, 0, 0) = AR(9)
ar_model = ARIMA(endog = df_boxcox_diff, order = (9, 0, 0))
ar_model = ar_model.fit()
ar_model.params


# Obtain predictions from the AR model for the testing data indices
ar_model_preds = ar_model.predict(start = train_len, end = len(df) - 1)

# Append the predictions with 'df_boxcox_diff' to prepare the data for inverse transformation
df_boxcox_diff_preds = pd.concat(objs = [df_boxcox_diff, ar_model_preds], axis = 0)

# Reverse the differencing transformation that was done on the data
df_boxcox_preds = df_boxcox_diff_preds.cumsum()
df_boxcox_preds = df_boxcox_preds.add(df_boxcox[0])

# Reverse the Box-Cox transformation that was done on the data
df_preds = np.exp(df_boxcox_preds)

# Plot the time series data with the train-test split and the testing data predictions
plt.figure(figsize = (14, 6))
sns.lineplot(data = df_train, x = 'Order Date', y = 'Sales', marker = 'o', color = 'blue', label = 'Train')
sns.lineplot(data = df_test, x = 'Order Date', y = 'Sales', marker = 'o', color = 'green', label = 'Test')
sns.lineplot(x = df_preds.index[train_len:], y = df_preds.values[train_len:], marker = 'o', color = 'purple', label = 'Predictions')
plt.title('Sales Data');

# Import 'mean_squared_error' from 'sklearn' for error computations
from sklearn.metrics import mean_squared_error

# Summarise the performance of the model on the test data using RMSE and MAPE
rmse = np.sqrt(mean_squared_error(y_true = df_test['Sales'], y_pred = df_preds.values[train_len:]))
mape = np.mean(np.abs(df_test['Sales'] - df_preds.values[train_len:]) / df_test['Sales'] * 100)

rmse = np.round(rmse, 2)
mape = np.round(mape, 2)

performance_df = pd.DataFrame(index = [0],
                              data = {'Model': 'AR', 'RMSE': rmse, 'MAPE': mape})

performance_df.set_index(keys = 'Model', inplace = True)

performance_df

# Define a function that scales the time series variable
# Note: Other scaling methods may be used as well
def scale_data(time_series = None, scaling_parameter = 1):

    # Scale the time series by a scalar value
    scaled_time_series = time_series / scaling_parameter

    return(scaled_time_series)

# Define a function to create input and output data points from the training data
# Note: Controllable parameters here are 'window_size' and 'window_stride'
def create_data_instances(time_series = None,
                          window_size = 1,
                          window_stride = 1):

    # Create lists for storing the windowed data
    X_train_data = []
    y_train_data = []

    # Iterate through the input time series data
    # Start from the first element of the input time series and stop at the first element of the last possible window
    # Use 'window_stride' as the step size in the loop
    for i in np.arange(0, len(time_series) - window_size - len(df_test), window_stride):

        # Extract and store the current X window
        data_point = time_series.iloc[(i):(i + window_size)]
        X_train_data.append(data_point)

        # Extract and store the y value(s) associated with the current X window
        y_val = time_series.iloc[(i + window_size):(i + window_size + len(df_test))]
        y_train_data.append(y_val)

    return X_train_data, y_train_data

You learnt how uncertainty is quantified in time series forecasting:

 

Confidence intervals (CI) capture uncertainty in the estimated mean of the process. They arise from uncertainty in model parameters such as level, trend, and seasonality.
 
Prediction intervals (PI) capture uncertainty in future observations. They include:
model uncertainty, and
random shocks that affect future values.
 
Prediction intervals are always wider than confidence intervals, since they account for more sources of variability.
 
As forecasts move further ahead in time, uncertainty accumulates, causing prediction intervals to expand with the forecast horizon.
 
Using intervals alongside point forecasts provides a more realistic picture of future behaviour and supports better risk-aware forecasting decisions.

Yes. This topic is much easier if we separate **three things**:

1. **Forecast** → our best single guess
2. **Confidence Interval (CI)** → uncertainty about the **estimated mean**
3. **Prediction Interval (PI)** → uncertainty about the **actual future observation**

The lecture's main distinction is exactly this: CI reflects uncertainty in the estimated mean/model parameters, while PI also includes the random shock that can affect the actual future observation.

---

# 1. Start with a simple example

Suppose we forecast monthly sales.

Our model says:

> **Next month's expected sales = ₹100 lakh**

So:

```text
Point forecast = ₹100 lakh
```

But ₹100 lakh is only our **best estimate**.

The actual sales could be:

```text
₹92 lakh
₹97 lakh
₹103 lakh
₹110 lakh
...
```

So we need a way to describe the uncertainty.

That's where intervals come in.

---

# 2. Point Forecast

First understand this:

```text
                 Forecast
                    ↓
                   ₹100L
                    |
                    |
--------------------●--------------------
```

The dot is our **point forecast**.

It means:

> "Based on the model, ₹100 lakh is our best single estimate."

But it doesn't tell us how uncertain that estimate is.

---

# 3. Confidence Interval — CI

A **confidence interval** is concerned with uncertainty around the **estimated mean/expected value**.

Suppose:

```text
Forecast = ₹100 lakh
95% CI = ₹96 lakh to ₹104 lakh
```

Conceptually:

```text
₹96L             ₹100L             ₹104L
 |----------------●-----------------|
          95% Confidence
```

The interval tells us about uncertainty in the **mean forecast**.

Your course describes CI as capturing uncertainty in the estimated mean of the process, arising from uncertainty in model parameters such as level, trend and seasonality.

---

# 4. Prediction Interval — PI

Now suppose we want to know:

> **"What could the actual sales next month be?"**

That's different.

Actual sales are affected not only by uncertainty in our model but also by **random shocks**.

For example:

* unexpected demand
* supply problem
* competitor promotion
* weather
* random customer behavior

So our prediction interval might be:

```text
Forecast = ₹100 lakh

95% PI = ₹88 lakh to ₹112 lakh
```

Visually:

```text
₹88L                       ₹100L                       ₹112L
 |---------------------------●---------------------------|
                  95% Prediction Interval
```

Notice that it is wider.

---

# 5. The BIG difference

This is the most important thing to remember:

### Confidence Interval

> **Where is the true mean/expected value likely to be?**

### Prediction Interval

> **Where could the actual future observation be?**

Think:

```text
CI → uncertainty about the MODEL'S MEAN
PI → uncertainty about the ACTUAL FUTURE VALUE
```

---

# 6. Why is Prediction Interval wider?

This is extremely important.

Suppose:

```text
Model uncertainty = ±4
Random future variation = ±8
```

For the mean forecast, we mainly care about model uncertainty.

So:

```text
CI ≈ ±4
```

But an actual future observation has:

```text
Model uncertainty
        +
Random shock
```

Therefore:

```text
PI > CI
```

Your course explicitly states:

> **Prediction intervals are always wider than confidence intervals**, because they account for more sources of variability.

So remember:

```text
CI
 |---------|
 
PI
 |-------------------|
```

---

# 7. A real-life analogy

Imagine a teacher predicts the **average marks** of a class.

She says:

> Expected average = 70

There is uncertainty around that estimated average.

That's similar to a:

**Confidence Interval**

But now ask:

> "What score will one particular student get?"

That individual student's score can vary much more.

That's similar to a:

**Prediction Interval**

So:

```text
Mean/average → CI
Individual future observation → PI
```

# 9. Why does uncertainty increase?

Imagine predicting tomorrow's sales.

You have reasonably recent information:

```text
Today → Tomorrow
```

There is some uncertainty.

```text
Today
 ↓
Tomorrow

Next day
```

At every step, new uncertainty can enter.

The errors accumulate.

\text{Forecast horizon} \uparrow

usually means:

$$
\text{Uncertainty} \uparrow
$$

and therefore:

$$
\text{Prediction Interval Width} \uparrow
$$

Be careful with the wording.

### PI

Used to quantify uncertainty around the **actual future observation**.
