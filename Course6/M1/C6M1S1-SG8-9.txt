Before implementing the model, it is crucial to interpret hyperparameters correctly. Although we discussed the parameter C in the theoretical formulation of SVMs as a measure linked to slack variables, the meaning of C in sklearn.svm.SVC() is inverted, acting as a regularisation strength. 

 

In theory:  A high C allows more misclassifications; more generalisable 

In sklearn: A high C penalises misclassification; more likely to overfit

Tuning Hyperparameter C
----------------------
With the baseline linear SVM model trained and evaluated, the next step is to refine its performance by selecting an appropriate value for the C hyperparameter. As discussed earlier, in scikit-learn’s implementation, C determines the penalty for misclassification, controlling how strictly the model separates the training data.

 

A very high C forces the decision boundary to classify nearly all training points correctly, which may lead to overfitting. A very low C relaxes this constraint, allowing a wider margin at the cost of misclassifying some points, thereby improving generalisation.

 

To ensure that this choice is not arbitrary, we will use Grid Search with cross-validation to systematically evaluate multiple C values. This allows us to compare performance across different configurations and select the one that provides the best balance between accuracy and generalisation.

The hyperparameter C determines the degree of this flexibility, linking SVM behaviour directly to the bias-variance trade-off.
