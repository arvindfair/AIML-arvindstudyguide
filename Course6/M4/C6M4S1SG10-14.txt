Which of the following best describes retrieval in a recommendation system? 

Selecting the single best item for a user 

Sorting all items in the catalogue 

Reducing a large catalogue to a smaller set of candidate items 

Predicting the exact next item a user will choose 

Answer
---------
Reducing a large catalogue to a smaller set of candidate items

Why: Retrieval is the first stage of a typical multi-stage recommendation pipeline (retrieval → ranking → re-ranking). Its job is to quickly narrow down a massive catalogue (potentially millions of items) to a much smaller candidate set (hundreds), using cheap, approximate methods (e.g., embedding similarity, ANN search, collaborative filtering signals). This is necessary because scoring every single item precisely for every user is computationally infeasible.

The other options describe different stages or misconceptions:

Selecting the single best item — that's closer to the final output after ranking/re-ranking.
Sorting all items in the catalogue — that's ranking, which happens after retrieval, and typically only on the smaller candidate set, not the whole catalogue.
Predicting the exact next item — this describes a specific task formulation (like next-item prediction), not the general purpose of retrieval.

Which of the following is an example of implicit feedback? 

A user giving a star rating 

A user marking an item as 'favourite' 

A user writing a review 

A user viewing an item page 


A user viewing an item page

Why: Implicit feedback is inferred from user behavior rather than explicitly stated preference — the user isn't directly telling the system "I like this" or "I don't like this." Viewing a page is a behavioral signal that suggests interest, but it's indirect and noisy (they might have clicked accidentally, or viewed it and disliked it).

The other options are all forms of explicit feedback, where the user directly and intentionally states their preference:

Star rating — a direct, quantified preference signal.
Marking as 'favourite' — an explicit, deliberate action indicating preference.
Writing a review — an explicit, detailed expression of opinion.

A useful mental model: implicit feedback = clicks, views, dwell time, purchases, scroll behavior (inferred intent). Explicit feedback = ratings, likes, reviews, thumbs up/down (stated intent).

In an LTR feature set, what does group_id typically represent? 

A unique identifier for each user 

The set of items being ranked for the same query or user 

The popularity score of each item 

The model used to generate the features 

The set of items being ranked for the same query or user

Why: In Learning-to-Rank (LTR), training data is organized into groups (also called "query groups"), where each group contains all the candidate items that need to be ranked relative to each other for a single query/user/session/context. The group_id tells the LTR algorithm (e.g., LambdaMART, XGBoost's rank:pairwise/rank:ndcg objectives) which items belong together so it can learn relative ordering within each group rather than comparing items across unrelated groups.

This matters because ranking is inherently a within-group comparison problem — you want item A ranked above item B for the same user/query, not comparing item A for User 1 against item B for User 2 on an absolute scale.

The other options are incorrect:

A unique identifier for each user — that would just be a user_id, not necessarily tied to grouping items for ranking.
Popularity score — that's a separate feature, unrelated to grouping.
The model used to generate features — group_id has nothing to do with model identity; it's a data structuring field.
