### Basic Transformation and Splitting Pipeline

Since our dataset has both numerical and categorical features, we will use a `ColumnTransformer` to apply scaling and encoding only where needed

This is wrapped inside a `Pipeline`, which ensures that all preprocessing steps are correctly applied inside each validation split, preventing leakage. While we could manually scale features before splitting, this would risk exposing information from the validation set to the model. 

By using a pipeline, we keep preprocessing tidy, reproducible, and evaluation-safe, then move on to comparing different validation strategies

numeric_features = X.select_dtypes(include=["int", "float"]).columns
categorical_features = X.select_dtypes(include=["category"]).columns

# ColumnTransformer allows us to apply different preprocessing to different column types
preprocess = ColumnTransformer(
    transformers=[("num", StandardScaler(), numeric_features),("cat", OneHotEncoder(handle_unknown="ignore"), categorical_features)]
)

# Pipeline joins preprocessing and modelling into a single estimator
model = Pipeline([("preprocess", preprocess), ("clf", LogisticRegression(max_iter=1000))])

The pipeline ensures that every fold in cross-validation receives its own independent preprocessing:
- When a fold is designated as training, the scaler and encoder are fitted only on that fold
- When the model predicts on the validation fold, transformation is applied using only what was learned from its training fold

scores


An important point to note here is that there are two ways we can use cross-validation

- First, to decide whether to choose a model. We apply cross-validation folds only on the training portion of the data. Once we know the model is suited for the task, we train the actual model on the whole training data normally. This is preferable when we have a sufficient amount of data.

- Second, to train the final model itself using cross-validation. Here, we use the `return_estimator` argument in the `cross_validate()` function, which returns the estimators as well from each fold. We can directly use the best estimator from these and perform a final evaluation using the test set. However, these estimators are each trained on only a fraction of the training data, and not guaranteed to be actually the best model. Although not recommended, this might prove useful in cases where we have access to only a small amount of data.

As we will see, this is not the case with `GridSearchCV`, which automatically refits the best model on the full training set, so the returned best_estimator_ is already ready for final testing.

cv_results = cross_validate(model, X_tr, y_tr, cv=kf, scoring="accuracy", return_estimator=True)  # this gives models from each fold

best_idx = scores.argmax()
best_cv_model = cv_results["estimator"][best_idx]
best_cv_model

Absolutely. **Stratified K-Fold** is basically a smarter version of normal **K-Fold**, especially when your target is a **classification problem**.

## 1. First: Normal K-Fold

Suppose you have **10 observations** and 2 classes:

| Observation | Class (Y) |
| ----------- | --------: |
| N1          |         0 |
| N2          |         0 |
| N3          |         0 |
| N4          |         0 |
| N5          |         0 |
| N6          |         1 |
| N7          |         1 |
| N8          |         1 |
| N9          |         1 |
| N10         |         1 |

So:

```text
Class 0 → 5 observations
Class 1 → 5 observations
```

Let's use **K = 5**.

Normal K-Fold divides the data into 5 folds, usually after shuffling:

```text
Fold 1 → N3, N7
Fold 2 → N1, N9
Fold 3 → N5, N6
Fold 4 → N2, N10
Fold 5 → N4, N8
```

Then we do 5 rounds:

```text
Round 1:
Training → Fold 2 + 3 + 4 + 5
Validation → Fold 1

Round 2:
Training → Fold 1 + 3 + 4 + 5
Validation → Fold 2

...

Round 5:
Training → Fold 1 + 2 + 3 + 4
Validation → Fold 5
```

Every observation gets used:

* **4 times for training**
* **1 time for validation**

---

# 2. What's the problem with normal K-Fold?

The problem occurs when classes are **imbalanced**.

Suppose you have:

```text
100 observations

Class 0 → 90
Class 1 → 10
```

If you randomly divide into 5 folds, you might get:

```text
Fold 1 → 20 observations → 20 class 0, 0 class 1
Fold 2 → 20 observations → 18 class 0, 2 class 1
Fold 3 → 20 observations → 19 class 0, 1 class 1
Fold 4 → 20 observations → 17 class 0, 3 class 1
Fold 5 → 20 observations → 16 class 0, 4 class 1
```

Fold 1 has **ZERO class-1 observations**.

That's not good for classification.

---

# 3. Stratified K-Fold solves this

**Stratified K-Fold tries to maintain the same class proportion in every fold.**

Suppose:

```text
100 observations

Class 0 = 90%
Class 1 = 10%
```

With **5 folds**, each fold should approximately contain:

```text
18 Class 0
 2 Class 1
----------------
20 observations
```

So:

| Fold      | Class 0 | Class 1 |   Total |
| --------- | ------: | ------: | ------: |
| Fold 1    |      18 |       2 |      20 |
| Fold 2    |      18 |       2 |      20 |
| Fold 3    |      18 |       2 |      20 |
| Fold 4    |      18 |       2 |      20 |
| Fold 5    |      18 |       2 |      20 |
| **Total** |  **90** |  **10** | **100** |

That's **stratification**.

It preserves the **class distribution**.

---

# 4. Simple real-world example

Imagine you're detecting fraud.

You have:

```text
1000 transactions

Non-fraud = 950
Fraud     = 50
```

So:

```text
95% Non-fraud
5% Fraud
```

Using **5-fold Stratified K-Fold**:

Each fold gets approximately:

```text
190 Non-fraud
10 Fraud
```

Then:

### Fold 1

```text
Training:
760 Non-fraud
40 Fraud

Validation:
190 Non-fraud
10 Fraud
```

### Fold 2

```text
Training:
760 Non-fraud
40 Fraud

Validation:
190 Non-fraud
10 Fraud
```

And so on.

Therefore, every validation set has roughly the **same 95:5 class ratio**.

# 5. Normal K-Fold vs Stratified K-Fold

| Feature                                       | K-Fold           | Stratified K-Fold |
| --------------------------------------------- | ---------------- | ----------------- |
| Splits data into K folds                      | ✅                | ✅                 |
| Every observation used for validation once    | ✅                | ✅                 |
| Every observation used for training K-1 times | ✅                | ✅                 |
| Maintains class proportions                   | ❌ Not guaranteed | ✅                 |
| Mainly useful for classification              | Sometimes        | **Yes**           |
| Useful for imbalanced classes                 | Less reliable    | **Very useful**   |

---

# 6. Python example

### Normal K-Fold

```python
from sklearn.model_selection import KFold

kf = KFold(n_splits=5, shuffle=True, random_state=42)

for train_index, val_index in kf.split(X):
    X_train = X.iloc[train_index]
    X_val = X.iloc[val_index]

    y_train = y.iloc[train_index]
    y_val = y.iloc[val_index]
```

### Stratified K-Fold

```python
from sklearn.model_selection import StratifiedKFold

skf = StratifiedKFold(
    n_splits=5,
    shuffle=True,
    random_state=42
)

for train_index, val_index in skf.split(X, y):
    X_train = X.iloc[train_index]
    X_val = X.iloc[val_index]

    y_train = y.iloc[train_index]
    y_val = y.iloc[val_index]
```

Notice one important difference:

```python
kf.split(X)
```

versus

```python
skf.split(X, y)
```

**StratifiedKFold needs `y` because it looks at the class labels to preserve their proportions.**

---

# 7. What happens in each fold?

Suppose:

```text
Class 0 = 80%
Class 1 = 20%
```

With 5-fold Stratified K-Fold:

```text
             100 observations
                    ↓
        ┌───────────┴───────────┐
        ↓                       ↓
    Class 0 (80)             Class 1 (20)
        ↓                       ↓
     distribute               distribute
     across folds             across folds
        ↓                       ↓
   ┌────┬────┬────┬────┬────┐
   F1   F2   F3   F4   F5
   16   16   16   16   16  → Class 0
    4    4    4    4    4  → Class 1
```

Each fold has:

```text
16 Class 0
 4 Class 1
```

So every fold maintains approximately:

```text
80% Class 0
20% Class 1
```

---

# 8. Very important: Stratified K-Fold does NOT mean training separately on each class

This is a common misunderstanding.

It does **not** do:

```text
Fold 1 → only Class 0
Fold 2 → only Class 1
```

Instead, **every fold contains both classes**, maintaining approximately the same proportion.

---

# 9. Why is this important for your ML exam?

Imagine a disease dataset:

```text
1000 patients

Healthy = 950
Disease = 50
```

If normal K-Fold accidentally creates a validation fold with very few or zero disease cases, your model evaluation can become misleading.

Stratified K-Fold ensures:

```text
Every fold ≈ 95% Healthy
Every fold ≈ 5% Disease
```

Therefore, performance such as **accuracy, precision, recall, F1-score, ROC-AUC** can be evaluated more consistently across folds.

---

## 🧠 Exam shortcut

Remember:

> **K-Fold:** Divide data into K folds randomly.

> **Stratified K-Fold:** Divide data into K folds while **preserving the class distribution in each fold**.

### One-line example:

```text
Dataset = 90% Class 0 + 10% Class 1
K = 5

Stratified K-Fold → each fold ≈ 90% Class 0 + 10% Class 1
```

### ⭐ Most important distinction

**Normal K-Fold → doesn't guarantee class proportions.**

**Stratified K-Fold → preserves class proportions.**

For a **classification problem, especially an imbalanced one, Stratified K-Fold is usually preferred.**

Confidence intervals reflect how much the performance might vary if the model were trained on different samples from the same population. A narrower interval indicates more stable behaviour, while a wider one signals uncertainty and potential sensitivity to training data. 

 

By comparing both mean performance and confidence bounds across different models or hyperparameter settings, we gain a stronger foundation for selection. A model with slightly lower average performance but tighter confidence may be preferable to one with a higher mean but large variability.

# Cross-Validation - Model Evaluation

Now, let's construct a reusable evaluation workflow. Rather than reporting a single score from one split, we quantify variation across folds - using confidence intervals. This helps estimate how a model may generalise to unseen data.

#### Why Confidence Intervals?

We saw that cross-validation produces a set of performance scores, not a single value. Let $(s_1, s_2, \ldots, s_k)$ denote the evaluation metrics obtained from $k$ folds.

We can estimate the mean performance and the variability across folds:

$$
\bar{s} = \frac{1}{k}\sum_{i=1}^{k}s_i
$$
$$
\sigma = \sqrt{\frac{1}{k-1}\sum_{i=1}^{k}(s_i - \bar{s})^2}
$$

To quantify uncertainty in the mean estimate, we form an approximate 95% confidence interval:

$$
\text{CI}_{95} = \bar{s} \pm t_{0.975,\space k-1}\cdot \frac{\sigma}{\sqrt{k}}
$$

(*For larger $k$, $t_{0.975,\space k-1} \approx 1.96$*)



This interval provides a plausible range for the model’s true generalisation performance based on the observed variability in cross-validation. A higher average score is meaningful only when accompanied by a narrow interval indicating low uncertainty.

Thus, we will use confidence intervals here to compare models more responsibly by considering both performance and stability.


#### Cross-Validation Evaluation Pipeline

Let's build a function to perform cross-validation and return:
- Mean performance
- Standard deviation across folds
- 95% Confidence Interval for the mean


def evaluate_cv(model, X, y, metric="accuracy", cv=5):
    scores = cross_val_score(model, X, y, scoring=metric, cv=cv)    # will take in the model, scoring criteria, and CV folds
    k = len(scores)
    mean = np.mean(scores)          # mean
    std = np.std(scores, ddof=1)    # std dev (ddof=1 as we are using the sample, not whole population)
    
    t_crit = t.ppf(0.975, df=k-1)   # t critical value
    
    # confidence interval bounds
    ci_low = mean - t_crit * (std / np.sqrt(k))
    ci_high = mean + t_crit * (std / np.sqrt(k))
    
    return {"Scores": scores.astype(float), "Mean": float(mean), "std": float(std), "CI": (float(ci_low), float(ci_high))}
