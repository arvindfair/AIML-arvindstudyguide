You learnt that the architecture of transformers begins with initial input embeddings. For example, if the input is a task to generate a Python program to print ‘Hello, world!’ This request is processed through attention models, which create richer representations of all the words in the input sentence, commonly called contextual embeddings, since each word’s representation depends on the surrounding words.

 

The encoder generates these contextual embeddings, which are then used by the decoder, which employs two types of attention models:

The first one is self-attention, which enables the decoder to focus on various parts of the current output sequence.
The second one is encoder-decoder attention, where the decoder attends to the encoder's outputs to incorporate context from the input sequence.
 

You understood this process using an example: "generating a Python program to print ‘Hello, world!’".

 



 

Encoder
This input Equation is transformed into a contextual embedding for each word in the sentence, using self-attention across all input tokens.
Decoder
The decoder starts with the first output token, such as ‘print’.
The token ‘print’ is then used to generate the next token in the sequence, such as a bracket ‘(’.
The sequence of tokens builds as "print" "(", followed by tokens such as "'", "Hello", ",", "World", "!", "'" and ")".
 
Iterative Generation
Each generated token, such as ‘print’, becomes the input for generating the next token, ‘(’.
 

This process continues until the entire code, “print(‘Hello, world!’)”, is generated.

 

During inference, each output token is fed back into the decoder to generate the next token, taking into account the input context and the previously generated tokens. This ensures that the model maintains coherence and aligns the final output with both the input context and the sequence generated so far.

The decoder attends to certain encoder outputs (such as Equation, Equation, and Equation) to determine the first word ‘print.’

2. How does each word get a richer representation?
Remember our group-project analogy?

Each word participates in the group project to improve its own understanding.

Every token creates three vectors:
- Query (Q): What information am I looking for?
- Key (K): What information can match another token's query?
- Value (V): What information can I contribute?
For six tokens, the encoder creates:

4. How is Z₂ calculated?
Here is the mathematical idea.

Z₂ represents the enriched representation of the word "program".

It is calculated as a weighted combination of all six Value vectors:
\[
Z_2 =
\alpha_{21}V_1+
\alpha_{22}V_2+
\alpha_{23}V_3+
\alpha_{24}V_4+
\alpha_{25}V_5+
\alpha_{26}V_6
\]

Where:
- \(V_1\) = Value of Python.
- \(V_2\) = Value of program.
- \(V_3\) = Value of to.
- \(V_4\) = Value of print.
- \(V_5\) = Value of Hello.
- \(V_6\) = Value of world.
- \(\alpha_{2j}\) = Attention weight assigned by program to token \(j\).
The attention weights are normalized using Softmax:
\[
\sum_{j=1}^{6}\alpha_{2j}=1
\]

This is a convex combination.

What does convex combination mean?

It means the weights are non-negative and add up to 1. Each Value contributes according to its assigned importance.

The same operation happens for every other token.
- Python gets its own attention weights and Z₁.
- Program gets its own attention weights and Z₂.
- To gets its own attention weights and Z₃.
- And so on.

Z₁, Z₂, Z₃, Z₄, Z₅, Z₆

Let's understand these individually.
Attention 1: Masked self-attention
Imagine the decoder has generated:
START, print


It now needs to determine what comes next.

It asks:
I have already generated START and print. What should I generate next?

The decoder uses self-attention over its own previously generated tokens.

It uses the relationships between those tokens to understand the output sequence so far.

Why is it called masked self-attention?

Because the decoder must not look at future tokens that it has not generated yet.

For example, when predicting the next token after print, it cannot look ahead at the correct answer and see ( or "Hello world".
Causal masking — what the decoder is allowed to see
Current position	START	print	(	Hello
START	✓	×	×	×
print	✓	✓	×	×
(	✓	✓	✓	×
Hello	✓	✓	✓	✓

✓ = can attend; × = cannot attend to future positions. This is an illustrative causal attention mask.
This prevents the model from cheating by looking at future answers.
Attention 2: Encoder–decoder attention (cross-attention)
After self-attention, the decoder also needs information from the original English instruction.

For example, the instruction is:
Python program to print Hello world.

The decoder has generated:
START, print


It needs to know what comes next.

It consults the encoder's six contextual representations:
\[
Z_1,Z_2,Z_3,Z_4,Z_5,Z_6
\]

It may learn to pay attention to the information associated with:
- Python
- program
- print
- Hello
- world
The decoder uses this information to determine the next output token.

The important distinction is:
Mechanism	Information it uses
Masked self-attention	Previous decoder tokens
Cross-attention	Encoder outputs

Technical detail: In cross-attention, the decoder supplies the Query, while the encoder outputs supply the Keys and Values.

That means:
\[
Q= \text{Decoder representation}
\]

\[
K= \text{Encoder representations}
\]

\[
V= \text{Encoder representations}
\]

This is different from encoder self-attention, where Q, K and V all come from the encoder's own input representations.

An important point from the lecture:

The encoder and decoder learn together.

If the encoder does not understand the input correctly, the decoder may not have enough useful information to generate the correct output.

Likewise, if the decoder is not generating the output correctly, the training process updates the relevant parameters throughout the model.

The learned Query, Key and Value projection matrices are updated through backpropagation and optimization.
One technical clarification: training versus inference
The lecture demonstrates generation during inference, where tokens are fed back one at a time.

During training, however, the correct target sequence is normally provided to the decoder in a shifted form. With causal masking, the decoder can calculate predictions for multiple target positions in parallel.

This is called teacher forcing.

So remember:
Stage	Decoder behavior
Training	Uses shifted correct target tokens; positions can be processed in parallel with masking
Inference	Starts with START and generates one token at a time

10. Important clarifications for deeper understanding
These details will help when you move into the mathematical lecture.

1. Attention is learned, not manually programmed. We might expect "program" to focus on "Python", but the actual learned weights depend on training, architecture and task.

2. The encoder does not generate the Python code. It generates contextual representations of the English input. The decoder generates the code.

3. The encoder and decoder do not have identical attention structures. The encoder uses self-attention; the decoder uses masked self-attention and cross-attention.

4. The attention output is not the entire Transformer block. The architecture also includes feed-forward networks, residual connections and normalization layers. These are important in the full mathematical explanation.

5. The six encoder vectors are not six complete meanings stored independently. Each is a learned vector representation containing contextual information.
