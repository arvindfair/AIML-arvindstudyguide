1. Why do we need attention?
Remember our previous encoder–decoder architecture?
- Encoder reads the entire input sentence.
- Encoder produces a final context vector.
- Decoder uses that context vector to generate the translated sentence.
The problem is that the basic architecture tries to compress the entire input sentence into one fixed-size context vector.

8. Exam revision — the complete flow
Remember these five steps
1. Encoder generates hidden states
   
   \(H_1,H_2,\ldots,H_{T_x}\)
2. Alignment function calculates scores
   
   \(e_{ij}=A(S_{i-1},H_j)\)
3. Softmax converts scores into weights
   
   \(\alpha_{ij}=\operatorname{softmax}(e_{ij})\)
4. Weighted combination creates context
   
   \(C_i=\sum_j\alpha_{ij}H_j\)
5. Decoder generates next word and updates state
   
   Uses previous output, previous state and current context.

Five terms you must know:
- Attention score: How relevant an encoder state is to the current decoder state.
- Alignment function: Learned function used to calculate attention scores.
- Softmax: Converts scores into weights between 0 and 1 that sum to 1.
- Attention weight: Relative importance assigned to an encoder state.
- Context vector: Weighted combination of encoder hidden states.
The most important sentence to remember:

Attention allows the decoder to decide what to focus on in the input sentence at each output-generation step, rather than depending on one fixed context vector.

# Limitations of Attention-Based Encoder–Decoder Models

The main limitation in your lecture is very important:

Even after adding attention, the encoder and decoder still use RNNs, and RNNs process words sequentially — one word after another.

Attention helps the decoder focus on the relevant input words, but it does not remove the sequential processing limitation of RNNs.

Let's understand why this is a problem and how it leads to Transformers.

The problem is the dependency on \\(H\_{t-1}\\).

## 6. One important clarification: Doesn't attention already solve this?

This is a common exam and interview question.

You just learned that attention calculates scores between decoder states and encoder hidden states.

So why is the model still slow?

Because attention and parallel computation solve different problems:

- Attention solves the problem of deciding which input information is relevant to the current output.
- Parallel computation solves the problem of processing sequence positions without waiting for previous recurrent steps.

Adding attention to an RNN does not remove the RNN's sequential dependency.

That is why attention-based RNN encoder–decoder models still have this limitation.

## Evolution of NLP architectures

1\. Traditional RNN encoder–decoder

Sequential processing, fixed context vector.

2\. RNN encoder–decoder with attention

Dynamic context at each output step, but still sequential RNN computation.

3\. Transformer

Uses attention without recurrent RNN layers, enabling parallel processing of input positions during training.

One technical nuance: Transformers remove recurrent processing in the encoder, but an autoregressive decoder still generates output tokens one at a time during normal translation or text generation. Parallelism does not mean every part of a Transformer runs simultaneously.

One-line exam answer:

The major limitation of attention-based RNN encoder–decoder models is sequential computation. Since each recurrent hidden state depends on the previous hidden state, processing long sequences becomes time-consuming. This motivates Transformer architectures, which enable parallel processing of input sequence positions using attention mechanisms.

In this session, you learnt how language modelling evolved from fixed word representations to sequence-to-sequence architectures and why the modelling context is critical for understanding and generating language. You began by revisiting word embeddings and examining how dense vectors capture semantic relationships while identifying the limitations of assigning the same representation to a word across all contexts. 

 

You then studied encoder–decoder architectures used in sequence-to-sequence tasks, learning how input sequences are encoded into internal states and how output sequences are generated step by step by the decoder. You observed how relying on fixed-size context representations leads to performance degradation on longer sentences. 

 

We introduced attention mechanisms as a way to overcome this limitation by allowing the decoder to dynamically focus on different parts of the input sequence at each prediction step. You learnt how attention scores are computed and how context vectors are formed. You also learnt how attention-based models are trained and how alignment between input and output sequences is learnt during optimisation. 

 

Finally, we discussed the drawbacks of recurrent encoder–decoder models even after introducing attention, particularly their sequential computation and limited scalability, which motivates the transition to fully attention-based architectures.
