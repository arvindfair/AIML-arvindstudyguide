You learnt that the encoder-decoder architecture is a popular framework for sequence-to-sequence tasks such as sentiment analysis. As the name suggests, the encoder-decoder architecture consists of two components - the Encoder and Decoder. The Encoder converts a sentence into a vector representation. The decoder uses this vector to perform the desired task, such as sentiment classification or translation.

 

This architecture uses a recurrent neural network (RNN) to handle context and generate accurate assessments. An RNN processes the context of a sentence sequentially. 


You then learnt how this model works with the help of the example sentence “The movie is good.”

 



 

In the Encoder, RNN processes the word “The,” performs matrix operations, and generates a context. 
This context is passed along with the next word "movie" to the next RNN cell. 
Each RNN cell takes the previous context and the current word to generate a new context. 
This process continues for each word in the sentence, with all RNN cells sharing the same weights, allowing the model to handle sentences of any length.
The final output is a rich vector representation of the sentence, capturing its context and meaning.
This vector is then fed into the Decoder, which uses a feed-forward neural network to classify sentiment, such as positive or negative.
 

Initially, the model might not be accurate, but through training and adjusting weights based on feedback, it learns to improve its predictions. While RNNs can struggle with long sentences because recent words might overshadow earlier ones, more advanced architectures such as LSTMs or bidirectional LSTMs can help mitigate this issue.


This encoder-decoder setup provides a more dynamic and context-sensitive representation of words than the static representations used in Word2Vec, enhancing performance in natural language tasks.

# Encoder–Decoder Architecture in NLP – Learn Visually

This lesson is the next step after understanding the limitations of Word2Vec, GloVe and FastText.

The central idea is:

Instead of understanding each word independently, let's process the entire sentence, build its context, and then use that context to perform a task.

We'll use the example from your lecture:

> "The movie is good."

Imagine you are developing a machine learning application that reads movie reviews and predicts whether the review is positive or negative.

Let's build the architecture step by step.

## 1. First, understand the big picture

An Encoder–Decoder architecture has two major components:

1. Encoder: Reads the input and converts it into a numerical representation containing information about the sentence.
2. Decoder: Uses that representation to produce the required output.

Think about a translator.

You give an English sentence:

"How are you?"

The encoder understands and represents the input. The decoder generates the translated sentence:

"आप कैसे हैं?"

The same architecture can perform different tasks:

| Application        | Input              | Output              |
| ------------------ | ------------------ | ------------------- |
| Sentiment analysis | Movie review       | Positive / Negative |
| Translation        | English sentence   | Hindi sentence      |
| Text summarization | Long paragraph     | Short summary       |
| Question answering | Question + context | Answer              |

The encoder–decoder is a framework. The exact decoder depends on the task.

## 2. Understand the Encoder using an RNN

Let's take our example:

"The movie is good."

How can a machine understand this sentence?

It cannot read the entire sentence like a human. An RNN processes it one word at a time.

RNN stands for Recurrent Neural Network.

The important concept is that an RNN carries information from the previous word to the next word.

Imagine reading a sentence and remembering what you have read so far.

## 3. What happens inside an RNN cell?

This is the most important concept in this lesson.

Every RNN cell receives two inputs:

- Current word (X): The word currently being processed.
- Previous hidden state (H): Information remembered from all previously processed words.

It combines both and produces a new hidden state.

## Inside one RNN cell

Mathematical representation

\\[ h_t = \tanh(W_x x_t + W_h h\_{t-1}+b) \\]

Don't worry about memorizing the formula yet. Understand what goes in and what comes out.

| Symbol         | Meaning                         |
| -------------- | ------------------------------- |
| \\(x_t\\)      | Current word vector             |
| \\(h\_{t-1}\\) | Previous context / hidden state |
| \\(h_t\\)      | Updated context / hidden state  |
| \\(W_x,W_h\\)  | Learned weights                 |
| \\(b\\)        | Bias                            |
| tanh           | Activation function             |

Same learned parameters reused at every time step.

Important: These are not four independently trained networks.

They are the same RNN applied repeatedly to different words.

Why is this useful?

Suppose you have:

- Sentence 1: 4 words
- Sentence 2: 20 words
- Sentence 3: 100 words

The same RNN cell and weights can process all these sequences. The number of processing steps changes, not the number of model parameters.

This is called parameter sharing.

### Which weights are updated?

There are two sets of learned weights in this example:

| Weights | Belong to            | Purpose                                         |
| ------- | -------------------- | ----------------------------------------------- |
| W1      | RNN Encoder          | Learn how to process words and preserve context |
| W2      | Feed Forward Decoder | Learn how to classify the sentence              |

The training process calculates the loss and uses backpropagation through time (BPTT) to update the RNN weights, along with backpropagation for the classification network.

This process repeats across many labelled examples.

### Very important: What about sarcasm?

Your professor makes an important point here.

Suppose your training data contains only:

- This movie is good. → Positive
- This movie is excellent. → Positive
- This movie is fantastic. → Positive

But it never contains sarcastic sentences.

Then you give it:

"This movie is so good it cured my insomnia."

Can the model reliably identify sarcasm?

No. Not necessarily.

Even though an RNN can preserve context, it still needs suitable training examples to learn the patterns associated with sarcasm.

This is an important distinction:

- Architecture provides the capability to learn.
- Training data provides the examples from which it learns.
- Training optimizes the model's parameters.

A powerful architecture with poor training data can still produce poor predictions.

## 7. What are the limitations of RNNs?

Now you might ask:

"If RNNs can remember previous words, why do we need LSTM, BiLSTM and Transformers?"

Good question!

The problem is that ordinary RNNs can struggle to preserve information from very early words in long sequences.

Consider:

> The movie, which was released several months ago and received many reviews from different critics, was surprisingly good.

When the RNN reaches `good`, it has processed many words.

Information from the beginning may become weaker as it repeatedly updates its hidden state.

This is related to the vanishing gradient problem during training.

### How do LSTM and BiLSTM help?

LSTM (Long Short-Term Memory)

LSTM is an improved type of RNN that uses gates to control what information should be remembered, updated or forgotten.

Think of it as a smarter memory system.

It has three important gates:

| Gate        | Responsibility                           |
| ----------- | ---------------------------------------- |
| Forget gate | Decides what information to discard      |
| Input gate  | Decides what new information to store    |
| Output gate | Decides what information to pass forward |

BiLSTM (Bidirectional LSTM)

A normal RNN processes words from left to right.

A BiLSTM processes the sentence in two directions:

- Forward: Left → Right
- Backward: Right → Left

Why is this useful?

Consider:

"I went to the bank to deposit money."

The word `bank` can use information from both its preceding and following words. The word `money` provides a strong clue about its meaning.

BiLSTM can combine information from both directions.

## 8. Encoder–Decoder: Classification vs Translation

One more important concept from your lecture.

The same general architecture can solve different problems by changing the decoder.

The decoder generates the output sequence one token at a time, using the encoded information and its previously generated tokens.

This is why it is called a Sequence-to-Sequence (Seq2Seq) architecture.

BLEU score
---------


When working with tasks such as machine translation, we need a way to automatically evaluate how closely a model’s output matches correct human translation. A widely used metric for this purpose is BLEU, which stands for Bilingual Evaluation Understudy. 

 

BLEU compares the model-generated sentence with one or more reference sentences written by humans and measures how much the two overlap in terms of words and short phrases. 

Instead of checking only individual words, BLEU checks n-grams, which are short sequences of consecutive words. It computes the following: 
Unigram precision (1-gram): How many individual words in the model output appear in the reference 

Bigram precision (2-gram): How many pairs of consecutive words match the reference 

Similarly, longer n-grams (3-gram and 4-gram) can also be used 
 

Matching longer n-grams is important because it reflects the correct word order and phrase structure, not just the correct vocabulary. 
 
BLEU then combines these n-gram precisions using a geometric mean and applies a brevity penalty if the model output is much shorter than the reference. This prevents the model from getting a high score by outputting only a few correct words. 
 

Let’s understand this with the help of an example where we compare one model’s output with a reference sentence using n-grams from 1 to 4.

Model output: “the cat is on mat”

BLEU is useful because it rewards correct words and correct phrase ordering, and allows fast, automatic evaluation over large data sets. 

 

However, BLEU also has limitations such as these: 

It does not directly measure semantic equivalence (same meaning with different wording) 

Valid paraphrases may receive low scores if phrasing differs from the references

## 4. Geometric mean — why does BLEU combine all four?

We have four precision scores:

| N-gram    | Precision |
| --------- | --------- |
| Unigram   | 1.00      |
| Bigram    | 0.75      |
| Trigram   | 0.67      |
| Four-gram | 0.50      |

BLEU combines these using the geometric mean.

\\[ GM=(P_1 \times P_2 \times P_3 \times P_4)^{1/4} \\]

Substitute the values:

\\[ GM=(1 \times .75 \times .67 \times .50)^{1/4} \\]

\\[ GM\approx0.71 \\]

Why geometric mean instead of ordinary average?

Because BLEU wants all the n-gram precision scores to be reasonably good. A low score for longer phrases should pull down the overall result.

Think of it this way: a sentence with correct individual words but badly arranged phrases should not receive an excellent score.

## 5. Brevity Penalty — why does BLEU punish very short translations?

This is another important concept.

Look at the two sentences again:

- Human reference: 6 words
- Machine output: 5 words

The machine omitted a word. What if a machine generated only:

`the cat`

Both words are correct, but the translation is incomplete!

Without a length penalty, a model could generate just a few common correct words and still get a high precision score.

BLEU solves this using Brevity Penalty (BP).

The formula is:

\\[ BP = \begin{cases} 1 & c \geq r\\\ e^{(1-r/c)} & c < r \end{cases} \\]

Where:

- \\(c\\) = number of words in the candidate (machine output)
- \\(r\\) = number of words in the reference (human translation)

In our example:

\\[ c=5,\quad r=6 \\]

Since the machine output is shorter:

\\[ BP=e^{(1-6/5)} \\]

\\[ BP=e^{-0.2}\approx0.82 \\]

## 7. Limitations of BLEU — what can go wrong?

BLEU mainly measures word and phrase overlap. It does not truly understand the meaning of a sentence.

Consider this example:

Human reference

The child is happy.

Machine translation A

The child is happy.

High word overlap

Machine translation B

The kid feels joyful.

Potentially low word overlap

Both translations express nearly the same meaning, but the second uses different words. BLEU may give it a lower score.

Three important limitations:

1. Semantic meaning: BLEU does not directly understand whether two sentences mean the same thing.
2. Paraphrasing: Different but valid wording can receive a low score.
3. Grammar and fluency: It does not independently verify whether the sentence sounds natural or is grammatically correct.

That is why BLEU is often combined with human evaluation and other semantic evaluation metrics.

To train a translation model, the data set must consist of aligned sentence pairs, where each source sentence corresponds to a target translation. These sentence pairs form the supervised learning signal that allows the model to learn how one sequence maps to another. 

 

Before the model can process the data, all text is converted into numerical forms, such as the following: 

Sentences are tokenised into integer sequences 

Vocabularies are built separately for source and target languages 

Sequences are padded so that all inputs in a batch have the same length 

 

Padding is necessary because neural networks operate on fixed-size tensors, whereas natural language sentences vary in length. 

 

The encoder processes the full input sequence and transforms it into internal hidden representations. These representations capture information about the entire source sentence and are passed to the decoder as the initial state. 

 

The decoder generates the output sentence step by step. At each time step, it uses the internal state received from the encoder (or from the previous decoding step) and the previous target token to predict the next word in the target sequence. This process continues until an end-of-sequence token is generated. 

 

This design allows the model to convert a complete input sequence into a complete output sequence, even when the two sequences have different lengths. 

 

After defining the encoder and decoder networks, the full training pipeline is set up using the following components: 

An optimiser (such as Adam) 

A suitable loss function for multi-class word prediction 

Checkpoint paths to periodically save model weights 

 

During training, batches of input and target sequences are passed to a training step function that performs the following operations: 

The input sequence is processed by the encoder to obtain hidden states. 

The decoder is initialised using the encoder’s final hidden state. 

Predictions are generated one time step at a time for the target sequence. 

 

Teacher forcing is applied during training, that is, at each decoding step, the correct target word from the data set is provided as the next input to the decoder rather than using the model’s own prediction. This stabilises training and allows the model to learn sequence patterns more efficiently. 

 

Loss is computed at each time step, averaged across the sequence length and used to update encoder and decoder parameters through backpropagation. Checkpoints are saved periodically so that training progress can be recovered if needed. 

 

Once training is complete, a separate evaluation procedure is used to generate translations. 

 

During inference, the decoder no longer receives the correct target words. Instead: 

The input sentence is first tokenised and padded. 

The encoder processes the sentence and produces initial hidden states. 

The decoder begins generating words starting from a special start token. 

 

At each step, the model selects the most probable next word and feeds it back as the input for the next prediction. This strategy is called greedy decoding. The process continues until an end-of-sequence token is produced or a maximum length is reached. 

 

This step-by-step generation process reflects how sequence models operate during real-world prediction. 

 

To measure translation quality, predicted sentences are compared with reference translations using the BLEU score. This metric evaluates the extent of overlap that exists between predicted and reference n-grams. 

 

To avoid cases where no n-gram overlap leads to zero scores, smoothing techniques can be applied during BLEU calculation. Although BLEU does not fully capture semantic correctness, it provides a useful quantitative indicator of translation performance during experimentation.
