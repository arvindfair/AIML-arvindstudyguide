# Introduction to Transformers — building the intuition

The central idea of this lecture is:

Transformers use attention to understand relationships between words, and parallel processing to avoid the sequential limitations of traditional RNNs.

Remember the previous lesson:

- RNN: processes words one after another.
- RNN with attention: can look back at relevant input words, but the RNN still processes sequentially.
- Transformer: uses attention as its central mechanism without requiring RNN recurrence.

Let's build this from the ground up.

## 1. Why were Transformers introduced?

Imagine this sentence:

What does it refer to? The animal.

To understand a word, we need information from other words in the sentence. This is called context.

A model must capture these relationships, even when the related words are far apart.

## 3. Encoder–Decoder architecture in Transformers

The encoder and decoder concepts have not disappeared. Their internal implementation has changed.

Think of a human translating a sentence:

1. Read the original sentence.
2. Understand its meaning and relationships.
3. Start producing the translated sentence.
4. Use the original meaning and what has already been translated to decide what comes next.

That is the basic encoder–decoder idea.

## Transformer encoder–decoder flow

Input sequence

X₁, X₂, X₃, ... Xₙ

## Encoder

Builds rich contextual representations

Z₁, Z₂, Z₃, ... Zₙ

## Decoder

Uses encoder information and previous outputs

Generated output sequence

Y₁, Y₂, Y₃, ... Yₘ

Conceptual encoder–decoder architecture described in the lecture.

### What does the encoder do?

Suppose the input is:

"The cat drinks milk."

The input initially consists of token representations:

- X₁ = The
- X₂ = cat
- X₃ = drinks
- X₄ = milk

The encoder enriches each token's representation using information from the other tokens.

For example, the representation of "drinks" should capture that the subject is "cat" and the object is "milk".

The encoder produces:

\\[ Z_1,Z_2,Z_3,Z_4 \\]

These are contextual representations, not simply copies of the original word vectors.

### What does the decoder do?

The decoder generates output tokens one at a time.

For each next token, it uses two sources of information:

1. Encoder outputs: What does the original input mean?
2. Previous generated outputs: What have I generated so far?

For example:

Illustrative translation generation

Encoder information

"I love apples."

Decoder generation

1. Generate "I"
2. Generate "love" using the input and previous output
3. Generate "apples" using the input and previous outputs

The output length does not have to equal the input length.

\\[ \text{Input length } N \neq \text{Output length } M \\]

For example, translating an English sentence into another language may require more or fewer words.

### The two kinds of attention in the decoder

This is an important concept for your exam.

| Attention type        | What does it look at?                  |
| --------------------- | -------------------------------------- |
| Masked self-attention | Previously generated output tokens     |
| Cross-attention       | Encoder outputs representing the input |

Why does the decoder need both?

- Self-attention helps it maintain the structure and coherence of the output.
- Cross-attention helps it refer to the original input.

We'll return to the distinction when studying the complete architecture.

## 5. How does the model calculate attention?

Let's convert the analogy into the actual mathematical process.

There are four major steps:

1. Step 1 — Calculate similarity

   Compare the Query with each Key.

   \\[ \text{Score} = QK^T \\]
2. Step 2 — Apply Softmax

   Convert the scores into attention weights that sum to 1.

   \\[ \alpha_i=\frac{e^{s_i}}{\sum_j e^{s_j}} \\]
3. Step 3 — Weight the Values

   Give more importance to the Values with higher attention weights.
4. Step 4 — Combine the Values

   Produce the final context-aware output.

   \\[ \text{Output}=\sum_i\alpha_iV_i \\]

Let's calculate a small example.

Suppose your query is compared against three keys and produces these similarity scores:

\\[ Scores=[1,2,3] \\]

Step 1: Softmax

\\[ Softmax(x_i)=\frac{e^{x_i}}{\sum_j e^{x_j}} \\]

The exponential values are approximately:

\\[ [2.718,\\;7.389,\\;20.086] \\]

## 6. How are Q, K and V actually created inside a Transformer?

The group-project analogy explains the meaning of Q, K and V. But how does a computer generate them?

This is where the actual Transformer mathematics begins.

Suppose the input sentence is:

> I love apples

First, the sentence is converted into numerical vectors (embeddings).

Each token embedding is passed through three different learned transformations.

## Creating Q, K and V

Input token embeddings

I · love · apples

Three learned linear transformations

Query

\\(XW_Q\\)

Key

\\(XW_K\\)

Value

\\(XW_V\\)

WQ, WK and WV are learned weight matrices. Every token gets its own Q, K and V vectors.

Mathematically:

\\[ Q=XW_Q \\]

\\[ K=XW_K \\]

\\[ V=XW_V \\]

Here:

- \\(X\\) = input token representations.
- \\(W_Q\\) = Query weight matrix.
- \\(W_K\\) = Key weight matrix.
- \\(W_V\\) = Value weight matrix.

These weight matrices are learned during model training.

Important: Q, K and V are not three separate pieces of information manually written by a person. They are three different mathematical representations created from the input.

- Key of "I"
- Key of "love"
- Key of "apples"

## 7. Self-attention versus cross-attention

This distinction connects the group-project example to the encoder–decoder architecture.

| Feature          | Self-attention                             | Cross-attention                             |
| ---------------- | ------------------------------------------ | ------------------------------------------- |
| Query comes from | Current sequence                           | Decoder                                     |
| Key comes from   | Same sequence                              | Encoder                                     |
| Value comes from | Same sequence                              | Encoder                                     |
| Purpose          | Understand relationships within a sequence | Connect decoder output to input information |

For example, when translating English into Hindi:

- Decoder Query: What information do I need to generate the next Hindi token?
- Encoder Keys: What information is available from the English sentence?
- Encoder Values: What information should be passed to the decoder?

This is why the Transformer decoder needs two attention mechanisms:

1. Masked self-attention over previous output tokens.
2. Cross-attention over encoder outputs.

## 8. How does parallelization happen?

Let's return to the most important motivation behind Transformers.

In an RNN:

\\[ H_t=f(X_t,H\_{t-1}) \\]

The next hidden state depends on the previous hidden state. This creates a sequential dependency.

In Transformer self-attention, all input token embeddings can be used to calculate Q, K and V together.

The model then calculates attention scores for all token pairs using matrix operations.

One technical detail to remember:

- During Transformer training, input positions can be processed in parallel.
- During autoregressive generation, the decoder normally generates output tokens one at a time because the next token depends on previous generated tokens.

So, parallelization does not mean that every operation in the entire Transformer happens simultaneously.

| --------------- | ------------------------------------------------------ |
| Transformer     | Architecture based on attention rather than recurrence |

| Encoder         | Creates contextual input representations               |
| Decoder         | Generates output tokens                                |
| Query (Q)       | What information am I looking for?                     |

| Softmax         | Converts scores into normalized weights                |

The entire attention mechanism in one formula:

\\[ \boxed{\operatorname{Attention}(Q,K,V) =\operatorname{softmax}\left(QK^T\right)V} \\]

This is the simplified form used in the lecture's intuition. The standard scaled dot-product attention formula used in the original Transformer is:

\\[ \boxed{ \operatorname{Attention}(Q,K,V) = \operatorname{softmax} \left( \frac{QK^T}{\sqrt{d_k}} \right)V } \\]

The division by \\(\sqrt{d_k}\\) is called scaling. It helps prevent large dot-product scores from making the Softmax distribution excessively concentrated.

A Transformer is essentially a system designed to read an entire sentence all at once, figure out how every word connects to every other word, and use those connections to understand context.

---

### 1. The Core Problem: Why RNNs Fell Behind

Before Transformers, language models used **Recurrent Neural Networks (RNNs)**.

* **The RNN way (Sequential):** An RNN reads word-by-word like a person whispering down a long line. By the time it reaches word 10 in *"The animal didn't cross the road because it was tired"*, the memory of *"animal"* from word 2 has faded. Worse, you cannot process word 8 until word 7 finishes. Modern GPUs want to compute everything at once; RNNs forced them to wait in a single-file line.
* **The Transformer way (Parallel + Direct Connections):** A Transformer takes all 10 words simultaneously. Every word gets a direct line of communication to every other word. When the word *"it"* needs to know what it refers to, it does not wait for a signal to pass through seven intermediate steps—it checks *"animal"* directly.

---

### 2. The Core Mechanism: Query, Key, and Value (Q, K, V)

To let words communicate, every token is given three distinct roles created by multiplying its embedding by learned weight matrices ($W_Q, W_K, W_V$):

* **Query ($Q$):** *"What am I looking for?"*
*(The word "it" asks: "Who was tired?")*
* **Key ($K$):** *"What do I offer / What is my tag?"*
*(The word "animal" advertises: "I am a living subject that gets tired.")*
* **Value ($V$):** *"What content do I actually pass along?"*
*(The semantic features and meaning of "animal".)*

```
          [ Query: "What am I looking for?" ]
                         │
                         ▼  (Dot product similarity)
          [ Key: "What label do I have?"    ]
                         │
                         ▼  (Softmax normalization)
               [ Attention Weight % ]
                         │
                         ▼  (Multiply weight × Value)
        [ Value: "Here is the actual info"  ]

```

#### The Math in 4 Steps

1. **Match ($Q \cdot K^T$):** Compare the Query of word $A$ with the Keys of all words. Higher dot product = higher relevance.
2. **Scale ($\div \sqrt{d_k}$):** Divide by the square root of the key dimension so numbers don't blow up and flatten gradients.
3. **Normalize ($\operatorname{softmax}$):** Turn the raw scores into percentages that sum to 100% ($1.0$).
4. **Mix ($\sum \text{weight} \times V$):** Multiply each word's Value vector by its percentage and add them up.

$$\operatorname{Attention}(Q, K, V) = \operatorname{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V$$

The result is a new vector for the word that now contains the context of every relevant neighbor.

---

### 3. Self-Attention vs. Cross-Attention

The full Transformer architecture splits into an **Encoder** (which reads and understands) and a **Decoder** (which generates new text).

| Feature | Self-Attention (Encoder & Decoder) | Cross-Attention (Decoder only) |
| --- | --- | --- |
| **Where $Q$ comes from** | Current sequence | Output being generated (Decoder) |
| **Where $K, V$ come from** | Current sequence | Input context (Encoder) |
| **Real-world analogy** | Roommates discussing chores among themselves | A student asking a teacher questions during an exam |
| **Purpose** | Connects words within the same sentence | Connects the generated translation back to the original text |

* **Masked Self-Attention:** Inside the decoder, future words are hidden ("masked") so the model cannot cheat by looking ahead at words it hasn't generated yet.

---

### 4. Parallel Training vs. Sequential Generation

A common point of confusion is whether Transformers are 100% parallel:

* **Training (100% Parallel):** Because the model already has the full input and target output, all attention scores and predictions across all positions are calculated in a single massive matrix multiplication pass.
* **Inference / Generating Text (Autoregressive):** When ChatGPT or a translation model writes a response in real-time, it generates token 1, feeds token 1 back into the decoder, generates token 2, and repeats. The generation itself is sequential, but each step's internal attention still runs in parallel across all generated tokens.
